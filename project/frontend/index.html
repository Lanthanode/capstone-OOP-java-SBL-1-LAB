Automated Multi-Account Quarterly Financial Servicing

In direct alignment with Experiment 11 Step 5, this subsystem processes quarterly interest accrual and fee levies across heterogeneous account types using Dynamic Method Dispatch (for (Account acc : portfolio) acc.applyPeriodicInterest();).

  • CurrentAccount: Evaluates commercial overdraft usage and levies a 3.0% fee on active credit drawn.
  • FixedDepositAccount: Computes compounding interest yield for term maturity.

1. Core OOP Concepts Implemented

  • Encapsulation: Private data fields with public accessors/mutators and state invariants.
  • Inheritance: Base class Account extended by SavingsAccount, CurrentAccount, and FixedDepositAccount.
  • Polymorphism: Method overloading (deposit(amt), deposit(amt, memo)) and Runtime Dynamic Dispatch (applyPeriodicInterest()).
  • Interfaces: Multiple contracts specified via TransactionProcessor, Auditable, and AccountDAO.
  • Custom Exception Boundaries: InsufficientFundsException (ERR-BANK-001) and OverdraftExceededException (ERR-BANK-002).
  • Multi-Dimensional Arrays: Preserved 2D transaction ledger String[100][4] for passbook statement generation.

2. Evolution into Capstone with DBMS & SQL

While Experiment 11 relied purely on transient in-memory memory arrays, this Capstone elevates the architecture into an industrial-grade enterprise solution by integrating Relational DBMS Persistence via SQLite and standard Java JDBC. It enforces ACID transactions, parameterized prepared statements to eliminate SQL injection, structured audit trails, and a real-time responsive web dashboard powered by standard Java SE HTTP Server.
